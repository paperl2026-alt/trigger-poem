### 晃动技术（已验证，入口 `晃动技术验证.bat` → `jiggle.html`）
- 单张立绘做 NIKKE 式运动，代码在 `src/jiggle/`，分三层：
  1. **身体层**：重心在两胯间移动（脚钉地）、上身绕腰摆、呼吸、屁股下沉（膝盖松）。
  2. **部件层**：裙摆、飘带、袖子下垂；尾巴和头发是链条，有行波；耳朵和头会转。
  3. **肉层**：22×34 软体网格，每个节点的软硬场决定弹簧参数。
     - 邻居相互耦合，力会传导：屁股 → 大腿，到膝盖为止。
     - 竖向压缩时横向鼓（保持体积）。
- 数据文件：
  - `public/jiggle/flesh.json`：软肉团、四肢、钉住点、躯干呼吸区、鼻尖。
  - `<pose>_w0..w3.png`：12 通道权重图，由 `tools/jiggle_masks.py` 生成。
  - `<pose>_rig.json`：线和枢轴。
  - `tools/flesh_preview.py`：预览软硬场。
- 用户反馈定下的规则：
  - **区域**：软肉"从上沿挂着、下缘最软"。
    - 猫娘：裙下尾巴根的臀部、腰侧。
    - 地雷妹：臀下缘的弧线、臀腿交界、侧乳。
  - **手感**：像果冻，有弹性和韧性，不是快速来回摇。核心约 2 Hz。
  - **站立射击**：持续的低频节奏弹动（滑条「射击节奏」，默认 1.6 Hz），不是"回弹次数"。
  - **射击时跟着枪晃**：每发一个快速的"枪震"（16 Hz 弹簧），地雷妹 13 发/秒也每发可见。
  - **呼吸**：站、蹲都一直有周期。越累越快越深。白气从**鼻尖**朝脸的方向呼出，不是从头或脑门冒。
  - **尾巴**不能带动小腿：尾巴链条的权重离开其他身体部位一段距离才生效（jiggle_masks.py 里的 `solo`）。
  - **汗液**：
    - 在皮肤上冒出 → 挂住长大 → 沿皮肤流下（出皮肤边就沿轮廓拐）→ 流干或碰到衣服就消失，身后留一道会干的水痕（`src/jiggle/sweat.js`）。
    - **不要往外飞溅**。

## 架构（2026-10-16 完成，推翻前先问用户）
本体也是一个"内容包"。DLC 和创意工坊的包用同一种格式叠加：同 id 深合并（可以只改一个数），新 id 新增。代码只写规则，数值、关卡、文字、图片清单都从包里读。

```
public/content/base/         本体内容包（每个 JSON 开头的 "_doc" 用中文写了每个字段是什么）
  pack.json                  包名、版本、order、enabled、requires、data（各类数据文件列表）、assets
  tuning/combat.json         战斗手感：血量、伤害、穿透、硬直递增、准星吸附、光束、连击、刷怪间隔、主角受伤/倒地/装填/偷看
  tuning/fever.json          Fever 三项的等级表、涨落速度、评价字母
  tuning/economy.json        评价奖励、熟练度表、背包扩容、新存档初始内容
  tuning/behaviors.json      敌人行为模板（walker/flyer/thrower/crawler/飞行物）的全部时间和距离
  tuning/layout.json         主角站位（半屏全身）、HUD 框
  tuning/settings.json       默认设置
  tuning/soft.json           旧版立绘晃动参数（以后换成 src/jiggle）
  characters/pink.json cat.json   枪械、必杀、姿势图、锚点、枪口、晃动区域
  enemies.json projectiles.json bosses.json items.json（道具效果 effects 是数据）
  episodes.json comics.json sets/school.json（房间、配色、站点、刷怪表、场景布置清单 dressing）
  text/ui.json theme.json    界面文字（中英日）、颜色/字体
  assets/                    图片 + manifest.json
mods/<id>/                   模组（DLC/工坊同格式）。开发时在项目根目录，打包后在 exe 旁边。mods/example 是示例（默认 enabled:false）
src/core/    引擎和底层服务：content.js（内容包加载器）、assets、audio、paper、particles、post、tween、input、i18n、save、settings、debug
src/battle/  战斗规则：game、world、level、player、enemies、boss、fever、fx、soft、characters、items
src/ui/      画面：screens、hud、comic（UI 会逐屏重做）
src/jiggle/  晃动和汗液（技术验证，之后接进 battle）
```

- 加载顺序：`main.js` 的 boot 先 `loadContent()`，再 initSettings、initSave、initLang、initTheme，最后加载图片。
- 代码在用到时才读 `C.*` 或 `T.*`（`T = C.tuning`），所以模组改的值会生效。
- 敌人"行为"是代码里的模板，数值由 `tuning/behaviors.json` 给，单个敌人可以在 `params` 里覆盖。Boss 用 `bosses.json` 的 `beh` 选代码里的行为类。
- 每类数据在 `content.js` 里有默认值，模组缺字段不会崩；数据出错记在 `C.errors`，不会卡死游戏。
- 存档里的旧角色 id（tsubaki/kagura）自动改名为 pink/cat；模组被删以后，存档里它加的东西会被忽略。
- 改数值的方法：打开对应 JSON 改数字，重开游戏即可。开发时运行 `node tools/fmt_json.mjs` 可以把 JSON 排版整齐。
- 还写在代码里没外置的：
  - 设置面板和 HUD 的少量界面文字（这两块 UI 要重做，到时一起进 text）；
  - 程序合成的音效参数（audio.js，以后换真实音频）；
  - 渲染和特效的细节常数。
- 便携版（`npm run portable`）已改成内嵌内容包，构建能通过，但**实际运行没验证**（预览窗口打不开本地文件）。
