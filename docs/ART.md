# 美术生产

## 来源和出图流程
- 美术全部由 GPT 出（Codex CLI 的出图工具），**只有静态 2D 图**：没有 3D 模型，没有蒙皮动画。动起来靠程序（晃动、浮雕、shader）。
- 一轮出图 = 一个 `tools/rounds/job_specsNN.py`：`JOBS = {任务名: [(输出路径, [参考图...], 提示词, "OPAQUE"?)]}`。
  1. `python -I tools/make_jobs.py tools/rounds/job_specsNN.py [任务名...]` → 生成 `art/jobs/<任务名>.md`（不进存档）；
  2. `bash tools/run_jobs.sh <并行数> 任务名...`（单个用 `tools/codex_job.sh art/jobs/X.md`）→ 图在 `art/raw/rNN/`；
  3. `python -I tools/rounds/rNN_import.py` → 进 `public/content/base/assets/` 和 `manifest.json`。
- 被拒（`*.refused.txt`）的常见原因：
  - 地雷妹设计稿的半透明粉色连衣裙 + "流口水、脸红、踢腿"之类的描述，会触发安全过滤。
  - 改法：去掉设计稿参考，写成"粉色荷叶边校服衬衫 + 薄荷水手领，fully clothed"，语气写 wholesome。
- Codex 有时会把图放大或挪位：用 `tools/fit_cutout.py` 搜缩放和偏移，对回参考图。
- **怎么给 Codex 下要求**（2026-10-17 用户："Codex 是弱智的，你需要很明确、很强硬地给建议"）：
  - 把视角、构图、轮廓、比例、什么必须有、什么绝对不许有，一条条写死，不留"自由发挥"；
  - 一个素材不确定能不能成，就一次出好几个**不同方向**的候选（不同物件、不同造型），挑合适的；
  - 现有素材不合适就重出，不拿别处的素材凑。
  - 画风统一靠**发参考图**（已定稿的场景 / 素材图），不靠文字描述；不规定光源方向，不要求符合现实。
  - **素材里不画特效**：发光、黏液反光、火花、光晕、闪光之类，程序能做的都不让 Codex 画进去（"不要让 codex 出的东西特效和资产叠一起"）。Codex 出干净的底子（物件、底图、准星底形之类），动起来、好看的部分由程序做（见「程序美术」）。
  - Codex / GPT 出的东西不是标准答案（"GPT 很多时候 SB 的要死"）：逐张检查，不合格就改、重出，或者换程序做。
- **多版本**（DESIGN「美术不许偷懒复用」）：凡是会在画面里重复出现的东西，一律出多个版本，游戏里轮换 / 随机，不让同一张相邻出现：
  - 场景：每侧墙每种至少 6 段不同的立面，地板、天花板各至少 3 张，贴花每种至少 3 个；
  - 掩体：一大关里不重复；
  - 杂鱼：每种怪至少 3 个造型版本（整套动作帧），刷怪时随机；
  - Codex 没有额度限制，并行多开。

## 有参考图时（UI 等），参考图就是标准答案
1. 在参考图上给每个零件画框（如 `art/ref/select_parts/boxes.json`）。
2. 让 Codex 原样单独画出零件：不许改造型、颜色，不许加东西，只去掉指定的字和控件。
3. 底图 = 参考图本身，只在控件盖住的地方用 Codex 补的像素（`tools/plate_mask.py`）。
4. 去掉控件上的文字：文字涂洋红让 Codex 补下面的纹理；平色区直接用周围颜色填（`tools/text_mask.py`）。
5. 文字由程序按实测的位置、字号、角度排（`tools/measure_text.py`，误差约 2px）。字体是打包的 Noto Sans SC 700/900。
6. 人物用参考图里的人物原样抠，不拿别处的立绘顶替。
7. 实机截图和参考图并排对照（`tools/node/shot.cjs` 截全尺寸），误差 1～2px 内。
- 已按此做完：标题+设置（`art/ref/ui_p5.png`）、选关（`art/ref/select_ref.png`）。

## 人物
- **立绘绝不复用**：
  - 每个画面、每个场景的人物重新画，姿势表情各不相同；
  - 同一张图换裁剪、缩放、重抠都算复用，让 AI 照旧姿势重画也算。
  - 执行：
    - 界面配置里的人物图写 `"char": true` 和 `"pose"`；
    - 出人物图前跑 `python -I tools/check_art_reuse.py --poses`，把已用过的姿势写进提示词"不许重复"；
    - 出图后跑 `--vs <新图>`，接进游戏后跑无参数版，必须通过。
- 角色设定只看 `art/ref/cat_sheet.png`、`art/ref/pink_sheet.png`。
- `art/gpt_sets/set_1..5` 是用户自己用 GPT 出的原始素材（战斗姿势、头像、漫画等），只当素材库，不搬到界面上。
- **战斗里的主角**：用晃动技术验证用的 NIKKE 式静态立绘 `public/jiggle/<cat|pink>_<cover|fire>.png`，加晃动骨架（见 TECH「晃动」）。
  - 不靠堆关键帧：R27 补的一堆姿势帧（`neko/*`、`pink/*` 里的 run、hurt、victory 等）不作为主做法。

## 怪物和 Boss
- 方向见 DESIGN「怪物」。
- 小怪：一张 3×2 的六姿势表（`tools/rounds/job_specs23.py`），`tools/rounds/r23_import.py` 按空白带切开，放进同一画布，存成 `enemy/<id>_<姿势>`。
- Boss（现行做法 R42，规矩见 DESIGN「Boss」）：
  1. 先想每个形态的镜头能看到她哪些部分，每个部分、每种样子单独出一张，每张至少 2 个版本（`_a` / `_b`，游戏里每次出现随机挑），参考定稿主图（`art/raw/r25/master.png`）统一画风；
  2. `tools/rounds/r42_import.py` 裁掉透明边存成 `boss/dc3_<形态>_<部件>_<版本>`，再跑浮雕（`tools/relief.py`）和留描边空白（`tools/pad_frames.py`，manifest 记 `pad`）；
  3. 各张画多宽、锚点在哪、弱点在哪、第三只眼在每张脸的哪里：`bosses.json` dc 的 `parts` / `weak` / `eyeAt`（按画出来的部分算，从左、从下的比例）；不合格的写进 `skip`。
- 小怪和 Boss 的帧都留了透明边（`tools/pad_frames.py`），给白描边和外光；道具也被留了边，`PanelWorld.relief` 按 `pad` 让画出来的底边落在地上。
- 所有站在场景里的东西（怪、掩体、道具），都用 `tools/relief.py` 生成深度浮雕图 `<key>_rd`（见下）。

## 场景（技术路线，2026-10-17 定，走廊验证已过）
- **场景 = 平板拼出来的真 3D 空间**：地板、墙、天花板、门窗都是平板。每块板贴 GPT 画的**正视图**，透视交给 3D。
  - 提示词要点（`tools/rounds/job_specs28.py` 的 FLAT）：
    - orthographic、完全正对、没有透视和消失点，画面就是这块表面，铺满到边；
    - 墙按 4.5m × 3m 一段出（3:2），地板 / 天花板 3m × 3m 一张，要能平铺。
  - 窗户玻璃涂纯洋红 `#FF00FF`，导入时抠空（`tools/rounds/r28_import.py`）；窗外是单独一张远景全景。
  - 地板、天花板导入时把边缘做成可平铺。
  - 贴花（眼睛符号、横幅、裂纹、散落的考卷、书包、粘液）出成一张 3×2 表，切开后贴在板上。
- **掩体、桌椅、道具、怪物、Boss = 单张 GPT 图 + 深度浮雕**：
  - `python -I tools/relief.py "<key 通配>"`：离线用 Depth Anything V2 Small（`tools/models/`，不进游戏、不进存档）算每个像素的远近，写 `<key>_rd.png` 并在 manifest 里登记 `relief`；
  - 游戏里把画推成凹凸网格，并用它打卡通光。
- **掩体**：专门出的前景路障（规则见 DESIGN「战斗」掩体）。
  - 画法：正面平视、平顶、宽而敦实、底边平直，就像从主角身后看过去的那一面；不画顶面俯视，不画地面和阴影，透明底；
  - 游戏里它比主角离镜头近，底部被画面下沿切掉，只露出上半截挡住她的下半身；
  - 摆放由程序按主角站位算（TECH「PanelWorld」掩体），关卡数据里只写用哪张图。
- **作废的路**（不要再走）：
  - 3D 网格 + 平铺照片式贴图；
  - 一张 GPT 场景画 + 深度模型鼓成假 3D（`plates.js`）；
  - 从固定视角把画投影到几何上；
  - GPT 单独画的整幅场景 CG 只能当风格参考（`art/ref/corridor_concept.png` 是风格参考）。

## 程序美术（shader / 粒子 / 程序动画）
Codex 只出静态底子；好看、会动的部分由程序做，几种手段按需混用（2026-10-17 用户）。想到新手段就记在这里。
- **已经在用的**：
  - 纸片浮雕 + 两段卡通光、墨线描边、纸纹（`paper.js`、PanelWorld 的描边 pass）；
  - 受损贴图（弹孔、裂缝，`DamageMap`）；
  - 主角晃动、汗、鼻息白气（`src/jiggle`）；
  - 射击特效：火光图 shader（拖影、色散、色相）+ 光晕星芒 + 冲击环 / 符咒环 + 火花、弹壳、符点、肉球、爱心粒子（`muzzle.js`）；
  - 怪物攻击：蓄力光团 + 吸入火花（`fx.charge`），声波环（`fx.soundWave`）；
  - Fever / 必杀的立绘轮廓光 + 外光晕，屏幕边缘泛光（`rig.js` aura，`post.js` edgeA / edgeB）；
  - 后期：色差、噪点、暗角、受伤红边、预警脉冲、翻页擦除（`post.js`）。
- **参考清单**（用户给的图：常见 2D shader 合集）：方向扭曲、源发光溶解、挤压、全息、全身发光溶解、外描边、强染色、故障、风吹、高斯模糊、压扁、UV 旋转、烟、换色、UV 扭曲、黑染、方向发光淡出、火焰、alpha 溶解、彩虹附魔、迷彩、附魔、冰冻、alpha 染色、饱和度、方向淡出、墨水扩散、亮度、锐化、棋盘格、彩虹流动、色相流动、全扭曲、色相、摆动、UV 滚动、像素化、阴影、彩虹、分离色调、世界平铺、叠加色相、只有描边、网点、毒、色相偏移、燃烧、自定义淡出、闪光、金属、对比度、叠加色、内描边；还有熔岩裂纹、电弧、半透明、粒子流、冰裂、扫描线、魔法阵 HUD（多层旋转圆环、刻度、光点）。
- **可用、还没用的**（用在哪写在括号里）：
  - 火焰：噪声 + 颜色渐变，不一定是正常颜色（粉火、紫火、黑火；鬼手真言、Boss 技能）；
  - 镭射 / 光束：滚动的条纹 + 两端光晕 + 抖动（猫娘必杀、Boss 激光）；
  - 抖动 / 故障：位移抖、RGB 分离、扫描线错位（受击、异变、精神污染）；
  - 精神污染（《主播女孩重度依赖》式）：色相乱转、像素排序、马赛克涌动、眼睛 / 符号贴片闪烁、文字雨（异变发生、Boss 阶段转换、低血）；
  - 马赛克变化：块大小随时间 / 位置变（转场、被打败的怪消散、审查梗）；
  - 金属光泽：matcap / 流动高光扫过（枪身、奖杯、HUD 金属边）；
  - 波纹：从一点扩散的扭曲环（命中、落地、喇叭怪声波、水面）；
  - 气泡 / 泡泡：上浮、晃动、破裂的粒子（黏液怪、汽水、可爱的过场）；
  - 粒子：火花、碎纸、弹壳、符文碎片、花瓣、灰烬；
  - 发光贴花：贴花底图 + 自发光脉冲（邪眼符号、裂缝、黏液）；
  - 网点 / 速度线 / 集中线（漫画感：必杀、暴击、转场）；
  - 溶解：噪声阈值溶掉 + 边缘发光（怪死亡、掩体被打烂）；
  - 热浪扭曲、水下扭曲（火、Boss 吐息）；
  - UV 流动：条纹、符文沿边框流动（HUD 线条、必杀充能环、准星）。
